## Как запустить

После запуска start.bat появится виртуальное окружение, с помощью которого сайт откроется на http://127.0.0.1:8000

Остановить через Ctrl+C в консоли.

## Что нужно

Python 3.8+
Зависимости в requirements.txt, при первом запуске установятся сами

## Какие функции меет сайт

- Регистрация и вход
- Создание, редактирование и удаление постов
- Три уровня видимости: публично, только подписчики, по запросу
- Подписка на пользователей и лента постов
- Теги для постов
- Комментарии

## Что я сделал

1. Архитектура

Использовал Django и паттерн MTV. Это стандартный способ организации кода в Django. Модели описывают, как выглядит база данных, views обрабатывают запросы и содержат логику, templates отвечают за HTML-страницы.

2. Модели и база данных

Сделал 5 моделей: пост, тег, подписка, запрос на доступ и комментарий. У каждого поста есть один автор (ForeignKey), но тегов может быть несколько и один тег может стоять на разных постах (ManyToManyField). В качестве базы данных использовал SQLite, так как она встроена в Python и не требует отдельной установки, вся база хранится в одном файле db.sqlite3.

3. Регистрация и авторизация

Реализовал регистрацию с проверкой: нельзя зарегистрироваться с уже занятым логином или email, пароли должны совпадать. После входа Django сам отслеживает сессию пользователя, не нужно каждый раз снова вводить логин. Страницы, доступные только авторизованным, защищены декоратором @login_required.

4. Система видимости постов

Три уровня доступа к посту: публичный, только для подписчиков и по запросу. В последнем случае читатель отправляет запрос, а автор сам одобряет или отклоняет его прямо на странице поста. Логика проверки доступа вынесена в метод can_view() модели поста.

5. Подписки и лента

Пользователь видит в ленте только посты тех, на кого подписан, плюс свои собственные. Подписка хранится в отдельной моделе Follow. Повторная подписка на одного человека контролируется в базе данных через unique_together.

6. Теги и комментарии

К каждому посту можно добавить теги. Они вводятся через запятую и сохраняются как отдельные объекты. По тегу можно кликнуть и увидеть все посты с таким же тегом. Комментарии привязаны к посту и пользователю, отображаются под постом в хронологическом порядке.

7. Шаблоны и интерфейс

Все страницы наследуются от одного базового шаблона base.html. Навигация, стили и общая структура описаны в одном месте. Использовал CSS-переменные для цветов, чтобы легко менять оформление. Добавил активное состояние у пунктов навигации и модальное окно со списком подписчиков.

## Что можно улучшить

- Сейчас все посты загружаются сразу одним списком. Если их будет несколько сотен, страница будет долго грузиться. Нужно добавить разбивку на страницы. В Django для этого есть встроенный пагинатор.

- Нет возможности найти пост по слову или найти пользователя по имени. Нужно добавить поле поиска и фильтрацию.

- У тестовых пользователей пароли "pass123" , что слишком просто. Django сам хэширует пароли при сохранении, но валидацию на минимальную длину и сложность лучше включить через AUTH_PASSWORD_VALIDATORS.

- Сейчас проверка, что редактировать пост может только его автор, написана вручную в каждом view. Лучше вынести это в отдельный декоратор или миксин, чтобы не повторять один и тот же код.
