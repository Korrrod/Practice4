## Как запустить

После запуска start.bat появится виртуальное окружение, с помощью которого сайт откроется на http://127.0.0.1:8000

Остановить через Ctrl+C в консоли.

## Что нужно

Python 3.8+
Зависимости в requirements.txt, при первом запуске установятся сами

## Что умеет сайт

- Каталог книг с фильтрацией по категории, автору и году
- Поиск с подсказками (Книга | Автор)
- Аренда на 2 недели, 1 месяц или 3 месяца
- Покупка книг
- Личный кабинет с историей
- Панель для администратора

## Что я сделал

1. Архитектура

Использовал Django и паттерн MTV. Это стандартный способ организации кода в Django. Модели описывают, как выглядит база данных, views обрабатывают запросы и содержат логику, templates отвечают за HTML-страницы.

2. Два типа пользователей

Обычный пользователь может смотреть каталог, арендовать и покупать книги. Администратор заходит через ту же форму входа, но попадает на панель управления /dashboard/.

3. База данных

Сделал 5 моделей: книга, категория, автор, аренда и покупка. У каждой книги есть один автор и одна категория, оба через ForeignKey. Аренда хранит период (2 недели, 1 месяц, 3 месяца), дату начала и конца, цену и флаг активности. Дата окончания считается автоматически при сохранении в зависимости от выбранного периода. Покупка привязана к книге и пользователю. В качестве базы данных использовал SQLite, так как она встроена в Python и не требует отдельной установки, вся база хранится в одном файле db.sqlite3.

4. Поиск и фильтры

Можно фильтровать по категории, автору и году. Есть текстовый поиск с выпадающими подсказками.

5. Аренда и покупка

Три варианта аренды с разными ценами. После аренды или покупки статус книги меняется автоматически.

6. Управление в админ-панели

Администратор может добавлять, редактировать и удалять книги. Есть раздел с пользователями и историей их аренд, а также список просроченных аренд.

7. Предупреждение об аренде

Если до конца аренды осталось меньше 3 дней — на главной странице появляется предупреждающий баннер с количеством оставшихся дней.

## Что можно улучшить

- Статус is_active, который отвечает за просроченные аренды, не меняется сам по себе, нужно добавить автоматическую проверку.

- Сейчас все посты загружаются сразу одним списком. Если их будет несколько сотен, страница будет долго грузиться. Нужно добавить разбивку на страницы. В Django для этого есть встроенный пагинатор.

- Сейчас просроченная аренда указывается только на баннере на сайте. Можно добавить уведомление на почту.

- У тестовых пользователей пароли "pass123" , что слишком просто. Django сам хэширует пароли при сохранении, но валидацию на минимальную длину и сложность лучше включить через AUTH_PASSWORD_VALIDATORS.
